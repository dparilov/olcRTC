OlcRTC VP8 Tunnel — Полный отчёт E2E тестирования

Дата: 16 апреля 2026 | Версия: feat/windows-full-tunnel (commit 0b34884) | Статус: E2E PASS

Результат

Полностью рабочий двунаправленный IP-туннель через видеоконференцию Яндекс.Телемост.

Данные инкапсулируются в VP8 видеофреймы и передаются через SFU как обычный видеопоток.

HTTP 200 за 0.52с | 10/10 стабильность | Exit IP = VPS

1. Архитектура

┌──────────┐ SOCKS5 ┌──────────┐ VP8 frames ┌──────────┐ VP8 frames ┌──────────┐ TCP ┌──────────┐ │Приложение│─────────→│ OlcRTC │────────────→│ Телемост │────────────→│ OlcRTC │──────→│Интернет │ │(браузер, │ 127.0.0.1│ Клиент │ WebRTC SFU │ SFU │ WebRTC SFU │ Сервер │прямое │ │ │curl) │ :1080 │(mode=cnc)│ │ (Яндекс) │ │(mode=srv)│соед. │ │ └──────────┘ └──────────┘ └──────────┘ └──────────┘ └──────────┘

Как это работает:

  1. SOCKS5 прокси принимает TCP-соединения от приложений на 127.0.0.1:1080
  2. VP8 кодирование: данные упаковываются в VP8 видеофреймы (0xFF маркер + длина + payload)
  3. WebRTC транспорт: фреймы передаются через Телемост SFU как обычное видео
  4. VP8 декодирование: на принимающей стороне фреймы распаковываются обратно в TCP
  5. Keepalive: VP8Sender генерирует interframes на 25fps, keyframe каждый 60-й

5. Ключевые технические находки

5.1 setSlots (КРИТИЧНО)

SFU Телемоста использует слот-модель для видео. Без setSlots WS-сообщения, SFU не форвардит VP8 треки.

{"setSlots":{"slots":[{"width":320,"height":240}],"audioSlotsCount":1,"key":1}}

5.2 tracks metadata в publisherSdpOffer (КРИТИЧНО)

SFU требует описание треков с mid, kind, groupId для регистрации публикуемых потоков.

{"publisherSdpOffer":{"pcSeq":1,"sdp":"...","tracks":[
  {"mid":"0","kind":"AUDIO","groupId":1},
  {"mid":"1","kind":"VIDEO","groupId":2}
]}}

5.3 AddTrack() vs AddTransceiverFromTrack(sendonly)

sendrecv (через AddTrack) позволяет SFU форвардить треки. sendonly блокирует форвардинг.

5.4 VP8 Data Transport

DataChannel не работает для данных — только VP8 фреймы. DC используется для сигнализации (hello, reset).

5.5 SFU Renegotiation

Обрабатывать ВСЕ входящие subscriberSdpOffer — SFU переподписывает треки при изменениях.
